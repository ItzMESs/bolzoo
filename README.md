# Болзоо Урилга — бүрэн сайт (Next.js)

Энэ бол backend-тэй бүрэн вэбсайт: хэрэглэгч бүр урилга үүсгэхэд **богино, цэвэрхэн линк** (`/i/xxxxxxxx`) авдаг, хайрт хүн нь хариулмагц **имэйлээр автоматаар мэдэгдэл** очдог.

## Хэрхэн ажилладаг вэ

1. Хэрэглэгч `/` дээр нэр, имэйл, өдрүүд, сонголтуудаа бөглөнө → `POST /api/invites` дуудагдаж, өгөгдөл Redis-д хадгалагдаад богино ID буцна.
2. Тэр ID-тай `/i/xxxxxxxx` линкийг хайрт хүндээ илгээнэ.
3. Хайрт хүн нээгээд "Тийм" гээд сонголтуудаа хийж дуусахад `POST /api/invites/[id]/respond` дуудагдана.
4. Энэ нь Redis-д хариуг хадгалаад, урилга үүсгэсэн хүний имэйл рүү **Resend**-ээр автоматаар мэдэгдэл илгээнэ.

## Байршуулах алхмууд (Vercel)

### 1. Кодоо Vercel дээр байршуулах
```bash
npm i -g vercel
cd bolzoo-fullsite
vercel --prod
```
эсвэл GitHub repo үүсгээд Vercel dashboard → "Add New Project" хийж болно.

### 2. Redis (Upstash) холбох — урилгын өгөгдлийг хадгалахад хэрэгтэй
1. Vercel dashboard → таны project → **Storage** таб → **Create Database**
2. **Upstash for Redis**-ийг сонгоод, чиглэлээ сонгоод үүсгэнэ (үнэгүй tier хангалттай)
3. Төслөө холбохыг санал болгоход "Connect" дарна — энэ нь `UPSTASH_REDIS_REST_URL` болон `UPSTASH_REDIS_REST_TOKEN` орчны хувьсагчуудыг **автоматаар** нэмнэ

### 3. Resend холбох — имэйл мэдэгдэл илгээхэд хэрэгтэй
1. [resend.com](https://resend.com) дээр үнэгүй бүртгэл үүсгэнэ
2. **API Keys** хэсгээс шинэ түлхүүр авна
3. Vercel dashboard → Settings → **Environment Variables** руу орж нэмнэ:
   - `RESEND_API_KEY` = таны авсан түлхүүр
   - `RESEND_FROM` (заавал биш) = `Bolzoo Urilga <onboarding@resend.dev>` — өөрийн домэйнтой бол Resend дээр баталгаажуулаад жинхэнэ хаягаа бичиж болно
4. **Санамж:** Домэйн баталгаажуулаагүй бол Resend-ийн туршилтын горимд зөвхөн ТАНЫ ӨӨРИЙН бүртгэлтэй имэйл хаяг руу л илгээж чадна. Жинхэнэ үйлчлүүлэгчид рүү илгээхийн тулд өөрийн домэйноо (жишээ нь bolzoo.mn) Resend дээр баталгаажуулах шаардлагатай — энэ нь DNS бичлэг нэмэхээс өөр зүйл шаарддаггүй бөгөөд ~10 минут л зарцуулна.

### 4. byl.mn холбох — QPay-ээр төлбөр авахад хэрэгтэй (заавал биш)
Энэ алхмыг хийхгүй бол урилга **үнэгүй** хэвээр ажиллана (төлбөрийн алхам огт харагдахгүй, шууд линк үүснэ). Төлбөртэй болгохыг хүсвэл:

1. [byl.mn](https://byl.mn) дээр бүртгүүлж, project үүсгэнэ (QPay merchant-аа тэнд холбоно)
2. Project-ийн тохиргооноос **API token** болон **Project ID**-г авна
3. Vercel dashboard → Settings → **Environment Variables** руу нэмнэ:
   - `BYL_API_TOKEN` = таны авсан token
   - `BYL_PROJECT_ID` = таны project ID
4. byl.mn dashboard → Settings → **Webhooks** руу орж, шинэ webhook нэмнэ:
   - URL: `https://<таны-домэйн>/api/webhooks/byl`
   - Event: `invoice.paid`
   - Үүсгэсний дараа өгөх **signing secret**-ийг хуулж авна
5. Тэр secret-ийг Vercel дээр `BYL_WEBHOOK_SECRET` гэдэг нэрээр нэмнэ
6. **Redeploy** хийнэ

Одоо урилга үүсгэх үедээ 3,000₮ төлбөрийн алхамтай болно: хэрэглэгч "Төлбөр төлөх" дарахад byl.mn-ийн хуудас руу очиж QPay-ээр төлнө, төлбөр батлагдмагц (webhook ирмэгц) урилгын линк автоматаар нээгдэнэ.

**Санамж:** byl.mn-ийн **тест горим (test mode)** дээр гүйлгээ дээд тал нь ₮50 хүртэл байдаг тул жинхэнэ 3,000₮-ийг турших бол project-оо **Live** горимд шилжүүлсэн байх шаардлагатай.

## Орон нутагт (local) турших бол
```bash
cp .env.example .env.local   # утгуудаа бөглөнө
npm install
npm run dev
```

## Дараа нь нэмж болох зүйлс

- **Админ панель**: `/admin` гэсэн хуудас нэмж, Redis дэх бүх урилгыг жагсааж, төлбөр баталгаажуулах, хариу ирсэн эсэхийг харах боломжтой (нэвтрэх нууц үг/токеноор хамгаална).
- **Төлбөр амжилтгүй болсон тохиолдол**: одоогоор хэрэглэгч төлбөрөө төлөхгүй орхивол урилга Redis-д "paid: false" хэвээр үлдэнэ (устгагдахгүй) — хүсвэл тодорхой хугацааны дараа автоматаар цэвэрлэх cron нэмж болно.
